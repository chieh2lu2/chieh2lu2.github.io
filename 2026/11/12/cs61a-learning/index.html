写 Python 程序时，除了最简单的函数，都该写文档字符串（docstring）。
按惯例，文档字符串用三引号括起来。第一行用一句话说明函数干什么，后面的行可以交代参数、讲清函数的行为：

def pressure(v, t, n):
        """Compute the pressure in pascals of an ideal gas.

        Applies the ideal gas law: https://en.wikipedia.org/wiki/Ideal_gas_law

        v -- volume of gas, in cubic meters
        t -- absolute temperature in degrees kelvin
        n -- particles of gas
        """
        k = 1.38e-23  # Boltzmann's constant
        return n * k * t / v

同时，配合文档测试（doctest）可以方便地测试函数。方法为文档字符串里放一段调用该函数的交互式示例：

def sum_naturals(n):
    """Return the sum of the first n natural numbers.

    >>> sum_naturals(10)
    55
    >>> sum_naturals(100)
    5050
    """
    total, k = 0, 1
    while k <= n:
        total = total + k
        k = k + 1
    return total

高阶函数

Python 中的某些函数可以接受其他函数作为参数，以及将函数作为返回值，这种函数叫作高阶函数。其中，函数作为参数和一种通用方法很好理解，但是之后就开始抽象了（其实只是我太笨了，悲）。我们一条条来梳理。

那我们这一节遇到了什么问题呢？我们之前的 improve 函数是这么写的：

def improve(update, close, guess=1):
     while not close(guess):
         guess = update(guess)
     return guess

其中 update 函数只有一个参数。但是，我们现在的迭代过程需要两个参数 和 。所以，我们把 a 放到外层函数里（或者说把 update 函数放在内层，使其能调用外层函数的 a 的同时只有一个参数），而这就是嵌套定义：

def sqrt(a):
    def sqrt_update(x):
        return (x + a / x) / 2
    def sqrt_close(x):
        return abs(x * x - a) < 1e-15
    return improve(sqrt_update, sqrt_close)


sqrt_update 创建时的帧是 sqrt，也就是他的 parent。所以他在访问 a 的时候会去找 sqrt 里的 a，而不是其他地方（比如全局的）a。局部定义的函数还能访问定义它们时所在作用域里的名字绑定，这种在嵌套定义之间共享名字的规则，叫作词法作用域。

内部函数能访问的是它们被定义时所在环境里的名字，而不是被调用时所在环境里的名字。

这要怎么理解呢？姑且管这种类型的嵌套函数（他有个正式的名字叫闭包，closures）叫 inner：

  • 定义时所在环境：执行 def inner 这一行时，Python 正在哪个 frame 里。
  • 调用时所在环境：执行 inner() 这一行时，Python 正在哪个 frame 里。
    不妨看个例子：
def outer():
    name = "outer"
    def inner():
        return name        # 在这里找 name
    return inner

def caller():
    name = "caller"
    f = outer()
    return f()             # inner 在这里被调用

print(caller())

输出是 outer，不是 caller。

  1. 执行 def inner 时，当前 frame 是 outer 的（里面 name="outer"）。
  2. inner 被返回，最后在 caller 里被调用；调用那一瞬间，当前 frame 是 caller 的（name="caller"）。
  3. inner 里找 name：自己的 frame 没有 → 去**“出生环境”** outer 找 → 拿到 "outer"。

所以，像 sqrt_update 这种局部定义，并且引用了外部环境的内容（就是能记住自己创建时的帧是什么），我们管这种函数叫闭包（本质上是函数与词法环境的绑定）。

Lambda 表达式

其实只是函数定义的一种简写，但是只能返回表达式，而不能赋值或者出现控制语句。

lambda x: x * x

def square(x):
    return x * x

这两种写法是完全等价的。需要注意的是，lambda 表达式求值后得到一个函数。

其他的都不怎么难，写一下最后的附加题 教堂 邱奇数（Church Numerals）吧。翻译一下题面：

逻辑学家阿隆佐·邱奇（Alonzo Church）发明了一种完全用函数来表示非负整数的系统。其目的是表明，函数足以描述整个数论：如果我们有函数，就不需要假设数存在，而是可以自行把数构造出来。

你的目标是在这个问题中重新发现这种被称为邱奇数的表示法。邱奇数是一种通过重复函数应用来表示非负整数的方法。具体来说，邱奇数（如下面的零、一和二）是函数：它们接收一个函数 f，并返回一个新函数；当这个新函数被调用时，会在某个参数 x 上重复应用 f 若干次。下面是零的定义，以及一个后继函数的定义：后继函数接收一个邱奇数 n 作为参数，并返回一个表示比 n 大一的邱奇数的函数：

def zero(f):
    return lambda x: x

def successor(n):
    return lambda f: lambda x: f(n(f)(x))

可能 lambda 函数看着很吓人吧！我们来解析一下这两个恐怖的 lambda 函数究竟说明了什么吧。

zero(f) 相对好理解：传入一个 f 函数，返回这样一个函数：对于给定的 x，返回 x。
也就是说不管 f 是什么，返回的都是一个函数，这个函数读入什么就输出什么，而和 f 没有关系。 return lambda x: x 就等价于：

def fun(x):
	return x
return fun

调用 zero 的方法就是 zero(f)(x)。

successor(n) 后继函数。这里的 n 应该能推测出来是一个邱奇数。n(f)(x) 代表着什么呢？不是很懂。先手算比较小的邱奇数吧。

接下来是加法。加法便是把 应用 次，再应用 次：

def add_church(m, n):
    """Return the Church numeral for m + n."""
    return lambda f: lambda x: m(f)(n(f)(x))

乘法。可以构想一个 已经应用 次的函数，再给他应用 次：

def mul_church(m, n):
    """Return the Church numeral for m * n."""
    return lambda f: lambda x: m(n(f))(x)

幂。这个就有点难了。我当时投机取巧是这样写的：

def pow_church(m, n):
    """Return the Church numeral for m ** n."""
    return lambda f: lambda x: m(f)(x) ** n(f)(x)

这样写只对于当 f 和 x 恰好是 church_to_int 的情境中是对的，随便举一个反例不妨看出其错误所在。
我们不妨先看 m(g) 和 n(f) 的意思。m(g) 即把函数 g 重复应用 m 次。n(f) 即函数 f 重复应用 n 次。而 用重复的话来说，就是 把「乘以 m」这个操作重复 n 次。 那这个返回的函数外层便是 n 了，主要探究什么函数是「乘以 m」——貌似就是 m 本身啊！实际上：

这就是我们想要的结果。答案：

def pow_church(m, n):
    """Return the Church numeral for m ** n."""
    return n(m)
